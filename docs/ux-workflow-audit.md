# 创作工作流与交互设计审计

更新于 2026-10-07。用户的主要工作流是批量生成候选图，挑选一张，再使用合适的模型继续编辑。此次迭代将导航、草稿和图片管理围绕这个过程重新组织；项目尚未发布，不迁移旧格式或旧图库数据。

## 核心判断与已交付行为

原界面把模型家族同时当作导航入口和草稿边界。用户以为自己只在切换模型，实际进入了另一份创作内容。普通生成始终占用中央画布，候选图又挤在底部短小的历史条中，进一步削弱了挑图与继续编辑的连续性。

| 用户任务 | 当前行为 |
| --- | --- |
| 生成多张候选图 | 普通生成使用候选网格；结果逐张发布和入库，已完成图片可立即使用 |
| 挑图并换模型编辑 | 明确携带所选图片进入编辑任务，默认使用最近的编辑模型；切换家族保留创作内容 |
| 编辑已有图片 | 编辑主图居首，主图与其他参考素材使用不同色框和文字角色标识 |
| 进行区域构图 | 显式开启画布；Runware FLUX 文生图所需区域直接启用。暂停的区域保留但不发送 |
| 找图、复用与管理图片 | 顶栏“图库”提供按日期排列的紧凑网格、来源/图板筛选、搜索、大图和多选 |
| 停止剩余候选 | “停止后续生成”只停止尚未发送的请求；当前请求继续接收与保存 |

主导航为生成、编辑、图库。模型家族、版本和供应商放在任务参数区。生成与编辑各有一份草稿和会话内撤销记录，每个模型路由独立记忆参数。新建方案返回参数页，生成张数随草稿保存。编辑页底部的生成记录可折叠，缩略图不再被压扁；普通生成直接使用候选网格。

## 挑图到编辑的衔接

生成记录、候选图和图库的使用动作绑定明确的图片身份。预览图片不修改任务，只有点击使用才改变草稿。切换模型、替换主图和添加参考素材可以撤销。

生成候选网格和图库资产都可以「用这张去 Edit」：把已入库的图片设为编辑主图，不必重新上传。用无关的新图片替换已有编辑内容时，弹窗展示新旧主图、当前编辑模型及将清空的内容，允许取消，并明确选择是否沿用其他参考素材。继续当前编辑结果则保留原参考素材，清空上一轮编辑指令。旧主图上的蒙版与区域不会悄悄转移到另一张图片；Create 的区域与蒙版也不会拷进新的 Edit 草稿。

主图固定为 API 输入第一张，重排同时更新精确图片标签。风格、主体、构图等参考用途编译为提示词，不添加供应商未支持的角色字段。不支持的蒙版会保留并阻止提交，提供移除入口；区域可明确暂停，切回 FLUX 后恢复。

FLUX 的来源框与目标框独立编辑。移动、固定、移除区域可打开对应参考图画布重新框选来源，或使用 0–1000 坐标微调。取消不改变草稿，应用可撤销；非主图和不同图片尺寸按来源图本身编译坐标。

## 图库和生成记录

图库拥有图片原图与缩略图。本机、剪贴板和 URL 导入先复制到受管目录；成功生成的每张图片立即入库，包括部分失败批次中的成功结果。工作区素材栏通过“从图库选择”复用同一网格，支持多选、预览、已使用标记与名额检查，按选择顺序追加，不再次复制图库文件。

图库大图使用原始比例，网格缩略图可以裁切。浏览和选择模式分开，返回和确认入口保持可达。生成记录保留请求参数、输入和蒙版快照、批次状态与费用，结果通过图库图片 ID 关联。

| 操作 | 保存与删除语义 |
| --- | --- |
| 删除图库图片 | 删除受管原图、缩略图和图库项；本机导入源文件不受影响 |
| 删除关联生成记录的图片 | 生成记录保留，结果标记已删除，禁止打开或导出；后续批次保存不会恢复图片 |
| 删除正在使用的图库图片 | 草稿工作副本仍可用，并标记来源已删除，不自动重新入库 |
| 删除生成记录 | 不删除图库资产；图片说明和搜索来源也随图库资产保留 |
| 入库失败 | 保留当前结果并提供保存重试，不重新发起付费请求 |

文件存储位于 `workbench/gallery/images/<assetId>/`，会话位于 `workbench/session.json`。删除按图片 ID 解析受管路径，先记录可恢复的删除状态；文件被占用时保留可重试入口。内部生成键防止重复保存与删除后复活。旧目录不扫描、不迁移。

## API 参数与结果信息

共享模型目录是前后端契约。控件按当前路由出现，请求只发送该路由白名单内的字段。当前目录为 6 个家族、12 个模型、47 条路由；控件覆盖包含自动/自定义尺寸、JPEG/WebP 压缩、扩写方式等有条件出现的字段。生成张数由应用队列控制，每次请求一张图片。

| 层级 | 内容 |
| --- | --- |
| 常用 | 模型、供应商、提示词、比例或尺寸、分辨率、张数 |
| 随任务出现 | 编辑主图、参考用途、来源/目标区域、蒙版、透明背景 |
| 高级 | 种子、质量、输出格式与压缩、扩写、审核，以及路由支持的思考与搜索 |
| 请求检查 | 实际发送值与最终提示词；切换路由时显示参数恢复或调整摘要 |

字段说明统一显示，复杂控件占整行。提示词计数使用编译后的 Unicode 字符数，包含参考用途与区域指令；超限内容不会截断，提交被阻止并显示当前路由限制。PNG 不发送有损压缩，关闭扩写不发送扩写方式。

Nano Banana 2.1 已接入 OpenRouter、Google、Comfy 与 Runware：1K/2K/4K、最多 14 张参考图，不接受 512 档。OpenRouter、Google 与 Runware 使用 14 种固定比例，Comfy 另有 9:21；除 OpenRouter 外可选自动比例。模型目录和原生请求映射均有离线测试。[OpenRouter 模型目录](https://openrouter.ai/api/v1/images/models)、[Google 模型说明](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)。

Google 的 Nano Banana 2.1 提供 minimal/medium/high，Nano Banana 2 提供 minimal/high，Pro 不提供思考级别控件。支持选择返回文字说明、思考摘要和联网搜索；图片搜索只向支持的模型开放。结果逐图保留来源页面、搜索词和搜索建议，思考阶段图片不进入最终图库。搜索建议在禁止脚本的 iframe 中显示，HTTP(S) 来源链接通过系统浏览器打开。[Google 图像生成文档](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)。

当前编辑使用有序图片与单次指令，不维持供应商多轮会话。视频输入、会话式聊天与队列优先级不属于本轮图像创作工作流。

## 验证

离线测试覆盖模型请求契约、蒙版保护、来源与目标坐标、参考图身份、HTML 安全隔离、SQLite 存储与图库迁移，以及删除后保存重试不会恢复资产。运行 `bun run test` 和 `cargo test --manifest-path src-tauri/Cargo.toml`；这些测试使用本地图片和 HTTP 模拟，不调用付费 API。整页交互不再通过模拟界面和中文文案匹配来验证，需在桌面应用中实测。

真实调用放在 `src-tauri/tests/live_nano_banana.rs` 与 `src-tauri/tests/live_creative_workflow.rs`，默认 `#[ignore]`。前者按供应商各计划两次付费请求；后者完整流程计划三次 Comfy 请求。设置 `LUTRIUI_TEST_CANDIDATE` 为已有 PNG 的绝对路径时，创意流程只做一次跨模型编辑。会话和图库使用当前契约，不扫描、不迁移旧目录。
